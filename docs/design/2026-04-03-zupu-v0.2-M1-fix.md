# Zupu v0.2 M1 问题修复与补充计划

根据 M1 阶段功能测试结果及讨论，本项目将修复以下两个主要问题：
1. **成员管理界面权限管控漏洞**：未加入家族的访客可操作数据；缺少直观的家族切换机制及无权限时的体验降级（修改请求）。
2. **加入其它家族的入口缺失**：用户无法搜索公开家族并申请加入。

## 1. 后端接口变更 (Backend)

### 新增探索与搜索接口
- **[MODIFY] [families.service.ts](file:///d:/coding/personalProj/zupu/apps/api/src/infra/families/families.service.ts)**
  - 新增 `exploreFamilies(userId, keyword)` 方法：查询 `accessLevel` 不是 `private`（即 `public` 或 `approval_required`）且名字或 code 匹配 `keyword` 的家族，可选过滤掉用户已加入的家族。
- **[MODIFY] [families.controller.ts](file:///d:/coding/personalProj/zupu/apps/api/src/infra/families/families.controller.ts)**
  - 新增 `GET /families/explore` 路由，调用上述服务。

### 权限拦截调整
- **[MODIFY] [edit-requests.controller.ts](file:///d:/coding/personalProj/zupu/apps/api/src/modules/edit-requests/edit-requests.controller.ts)**
  - 将 `create` (提交修改请求) 方法的权限要求从 `@Roles('collaborator')` 降低到 `@Roles('viewer')`。
  - 这样确保：只有**加入该家族**（至少拥有 `viewer` 权限）的用户才能提交修改请求，未加入的访客直接被后端 `RolesGuard` 拦截（返回 403 HTTP 错误）。

## 2. 前端服务与页面变更 (Frontend)

### 2.1 增加 Explore 接口并重构 MembersPage
- **[MODIFY] [api.ts](file:///d:/coding/personalProj/zupu/apps/web/src/services/api.ts)**
  - 增加 `exploreFamilies(keyword)` 的请求封装。
- **[MODIFY] [MembersPage.vue](file:///d:/coding/personalProj/zupu/apps/web/src/pages/MembersPage.vue)**
  - **家族选择器**：若用户有已加入的家族，页面顶部显示下拉框组件（从 `authStore.families` 获取），选中项与 `authStore.currentFamilyId` 双向绑定，切换时加载该家族成员。
  - **权限视图与阻断逻辑（核心）**：
    - **访客态**：如果用户未加入任何家族（或由于切换导致没有任何合法权限），彻底隐藏“添加成员”表单和列表中的操作列。
    - **查看者（Viewer）**：保留新增/编辑/删除等入口，但点击时不再直接调用 `create/update/deleteMember`，而是弹出专属的“修改请求(EditRequest)”对话框，让用户填写理由，然后调用 `submitEditRequest`。
    - **直写者（Creator/Admin/Collaborator）**：维持现有逻辑，点击后直接发起创建/修改。
  - *交互细节*：如果处于“查看者”状态，按钮上可以附加提醒文案（如通过 Hover 提示“将发起修改请求”）。

### 2.2 在“家族管理”页面添加加入入口
- **[MODIFY] [FamilyManagePage.vue](file:///d:/coding/personalProj/zupu/apps/web/src/pages/FamilyManagePage.vue)**
  - 顶部增加标签页或区块拆分，区分为“我的家族”和“搜索与加入新家族”。
  - **搜索与加入新家族**区块：
    - 提供输入框供用户根据名称或代码搜索系统中的其他家族。
    - 对于搜索结果项，提供「申请查看权限」和「申请协作权限」两个动作按钮。
    - 点击后若家族配置为 `approval_required` 时，可弹出输入框让用户填写“申请理由”，再调用已有的 `submitAccessRequest(familyId, type, reason)` 接口。

## 3. 验证计划
- 分别用 Admin 用户（或 Creator）和新建的访客用户登录。
- **验证搜索与申请**：访客在家族管理页面搜索 Admin 的家族并请求成为 Viewer/Collaborator，确认请求流转正常。
- **验证未加入时的成员管理**：访客进入“成员管理”页面应看不到表单/操作列。
- **验证 Viewer 的修改请求**：访客变为 Viewer 后，在“成员管理”页面新增成员或修改成员，系统应提示填写理由并产生新 `EditRequest` 数据，并不直接写入数据库。
- 后端直接抛出的未经授权 `EditRequest` 请求将被 403 异常拦截。

# Zupu v0.2 M1 相关问题修复与收尾

在确认上述测试过程发现的漏洞后，我们完成了针对未加入家族用户和权限不足用户的相关修改，使得 M1 阶段真正收拢为一个完整可用的申请/修改闭环链路。

## 重大交互体验升级
### 1. 家族页面的「发现」功能
过去我们只有「我的家族」，现在您可以在 `FamilyManagePage` 面板下方进入**🔍 搜索与加入新家族**板块。
- 支持关键词模糊检索（搜索所有配置为 `public` 或 `approval_required` 的非私有家族）。
- 输入心仪的家族名称/代号后，点击**“申请查看”**或**“申请协作”**即可发起授权流程。

### 2. 成员管理页面的安全把控 (MembersPage)
针对前次反馈的安全漏洞，现在成员页面做出了以下分层权限梳理：
- **无家族状态**：完全隐藏了左侧与上方的添加、修改表单部件。如果您没有任何家族，您将只看到“您尚未加入任何族谱”的拦截占位卡片。
- **全局家族切换**：页面顶部新增了“当前管理的族谱”选择器，与全局家族状态保持同步，切换更直观。
- **自动降级拦截**：如果你仅拥有某族谱的 `viewer`（查看者）身份，当您在此页面点击任何“新增”或“删除”触发器时，系统将不再继续处理写入流程，而是弹出一个收集理由的弹窗，将您的操作自动降维打包为 `EditRequest` (修改请求) 直接推送给该族谱的管理员/创建者审核。

## 涉及的代码变更点

- [NEW] **后端 Families Module**:
  - `families.service.ts`: 新增用于公共发现的 `exploreFamilies` 接口，根据权限 `accessLevel` 以及用户的加入状态进行精确屏蔽和查找。
  - `families.controller.ts`: 添加 `GET /families/explore`。
- [MODIFY] **后端 EditRequests 配置**:
  - `edit-requests.controller.ts`: 将 `create` (新增请求) 方法从 `@Roles('collaborator')` 下调到了 `@Roles('viewer')`。这意味着只看不写的普通用户能够有权利申请修改家族数据，非此家族的访客会再次被抛弃拦截（阻断了最初报告中随意跨家族创建请求的漏洞）。
- [MODIFY] **前端服务及界面**:
  - `api.ts`: 暴露出 API 端点以供外部调用（支持关键词查询等参数）。
  - `MembersPage.vue` & `FamilyManagePage.vue` 进行大幅重构与补充渲染（新增 Select 组件下钻与基于角色的鉴权阻断）。

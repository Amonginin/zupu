# Zupu v0.2 M1 阶段功能测试报告

## 发现的遗留问题

在 M1（权限与修复）阶段的前后端开发完成后，经测试发现如下逻辑漏洞与交互缺失：

### 1. 成员管理的越权新建问题
- **现象**：任意访客进入“成员管理”页面并执行“添加成员”、“修改”或“删除”等操作时，会直接修改数据库并在所选家族中产生真实数据变化。系统目前即使通过了拦截验证，前端也没有基于用户角色权限去控制表单。
- **原因**：目前的前端页面（如 `MembersPage.vue`）尚未基于用户当前选择家族的角色（`creator`, `admin`, `collaborator`, `viewer`，或无权限访客）进行操作控制的区分，也没有按设计接通触发 `EditRequest` （修改请求）的逻辑。应当只有对应家族的“创建者”、“管理员”或“协作者”能直接修改数据。

### 2. 角色与权限的申请入口缺失
- **现象**：系统无法找到申请获取某家族“协作者”或“查看者”身份的前端入口。
- **原因**：现有的“族谱管理（Family Manage）”页面仅展示了“我的族谱”（自己创建或有关联角色的族谱）。目前仍缺少一个让访客主动搜索、发现其他族谱，并提交 `AccessRequest`（协作/查看申请）的功能入口或页面。

---

## 需优化的方向建议
1. **完善成员页面的权限边界绑定**：根据当前用户在当前选定族谱中的真实角色，隐藏敏感操作控件，或将“直接保存”自动降级为“提交修改请求”。
2. **构建全域族谱搜索与申请链路**：提供一处可以按名称或代码搜索系统内已有族谱的功能区域供新用户发起权限申请流程。
